Windows · il2cpp_windows.py

بازیابی metadata، اجرای dumper موجود و فیلتر dump.cs با منوی تعاملی و CLI. به Python 3.8 یا جدیدتر نیاز دارد و خود اسکریپت وابستگی Python شخص ثالث ندارد. منظور از Windows، سیستم اجرای ابزار است: ورودی کتابخانه باید Android ELF یعنی libil2cpp.so باشد؛ GameAssembly.dll ورودی پشتیبانی‌شدهٔ این اسکریپت نیست.

هیچ dumperی دانلود نمی‌شود. Il2CppDumper.exe را از قبل تهیه کنید و در پوشهٔ جاری یا کنار اسکریپت قرار دهید، یا مسیرش را با --dumper-exe بدهید.

python --version
python il2cpp_windows.py
# Extracted inputs / فایل‌های استخراج‌شده
python il2cpp_windows.py --lib "C:\game\libil2cpp.so" --metadata "C:\game\sysinfo.dat" --out "C:\il2cpp_result" --dumper-exe "C:\Tools\Il2CppDumper.exe"
# Recovery only / فقط بازیابی
python il2cpp_windows.py --lib LIB --metadata META --out OUT --no-dump
# APK: still prompts for candidate numbers / همچنان انتخاب شماره لازم است
python il2cpp_windows.py --apk "C:\game.apk" --out "C:\il2cpp_result" --no-dump

در بازیابی، خروجی OUT/global-metadata.dat است. در حالت APK، کتابخانه در OUT/libil2cpp.so و metadata ورودی در OUT/metadata_input.bin نیز ذخیره می‌شود. با ورودی استخراج‌شده، کتابخانه کپی نمی‌شود. dumper با آرگومان‌های مسیر library، metadata بازیابی‌شده و OUT/dump اجرا می‌شود؛ پوشهٔ کاری فرایند، پوشهٔ exe است.

شکل قدیمی LIB METADATA OUTPUT_DIR دیگر پشتیبانی نمی‌شود؛ فقط گزینه‌های نام‌دار را استفاده کنید. نبودن exe در CLI پیام می‌دهد و کد 2 برمی‌گرداند؛ metadata بازیابی‌شده باقی می‌ماند. در منوی بازیابی، نبودن exe فقط پیام می‌دهد و به منو برمی‌گردد. خروج موفق exe به‌تنهایی به معنی بررسی وجود dump.cs توسط نسخهٔ ویندوز نیست.

Android · Termux + Python Dumper

به Python 3.10+ نیاز دارد. وابستگی‌های dumper را طبق README مخزن آن نصب کنید.

pkg update
pkg install python git -y
termux-setup-storage
python --version
# Run beside your APK files / اجرا کنار فایل‌های APK
python il2cpp_android.py

انتخاب محل dumper و تأیید دانلود

در ترمینال تعاملی، اگر --dumper-dir یا --dumper-script ندهید، محل را انتخاب می‌کنید: ۱) پوشهٔ home، ۲) کنار اسکریپت، ۳) مسیر دلخواه. این انتخاب، جست‌وجوی خودکار هم‌زمان در چند پوشه نیست. در مسیر دلخواه، اگر نام پوشه Il2CppDumper-Python نباشد این نام به انتهای مسیر افزوده می‌شود.

اگر مخزن موجود نباشد، دانلود با سؤال [y/N] تأیید می‌شود؛ Enter یعنی خیر. در حالت غیرتعاملی، مسیر پیش‌فرض ~/Il2CppDumper-Python است و دانلود فقط با --yes مجاز است. --no-clone دانلود را ممنوع می‌کند. مخزن معتبر باید il2cpp_dumper_py/__main__.py داشته باشد؛ وجود پوشهٔ ناقص خطاست.

# Use an existing repository / استفاده از مخزن نصب‌شده
python il2cpp_android.py --apk /sdcard/Download/game.apk --out ~/il2cpp_result --dumper-dir ~/Il2CppDumper-Python --no-clone
# Permit download if missing / اجازهٔ دانلود در صورت نبودن مخزن
python il2cpp_android.py --apk /sdcard/Download/game.apk --out ~/il2cpp_result --yes
# Extracted inputs; recovery only / فایل‌های استخراج‌شده؛ فقط بازیابی
python il2cpp_android.py --lib /sdcard/Download/libil2cpp.so --metadata /sdcard/Download/sysinfo.dat --out ~/il2cpp_result --no-dump

مخزن به شکل python -m il2cpp_dumper_py LIB META OUT/dump با پوشهٔ کاری مخزن اجرا می‌شود. --dumper-script مسیر یک فایل موجود را می‌گیرد و آن را با Python و همان سه آرگومان اجرا می‌کند؛ DLL یا exe را به آن ندهید. فایل ورودی library و metadata بازیابی‌شده در OUT ذخیره می‌شوند. موفقیت دامپ نیازمند کد خروج صفر و dump.cs غیرخالی در OUT/dump یا OUT است.

اگر dumper موجود نباشد و دانلود رد یا غیرفعال شود، اجرای Android با کد 0 تمام می‌شود ولی فقط فایل‌های بازیابی‌شده را دارید؛ این وضعیت موفقیت دامپ نیست. --no-dump نیز بلافاصله پس از ذخیرهٔ ورودی‌ها برمی‌گردد و حتی با -f فیلتر پس از دامپ اجرا نمی‌شود. در این فایل تابعی به نام metadata_dump() وجود ندارد.

اجرای تعاملی و انتخاب APK

Windows

  1. بدون آرگومان، منوی اصلی باز می‌شود: ۱ بازیابی/اجرای dumper، ۲ فیلتر dump، ۰ خروج.
  2. در بازیابی، ۱ APK یا ۲ library + metadata استخراج‌شده را انتخاب کنید؛ حالت پیش‌فرض استخراج‌شده وجود ندارد.
  3. مسیرها و خروجی (پیش‌فرض ./il2cpp_result) را بدهید. عدد 0 در promptهای مشخص‌شده یعنی بازگشت.
  4. پس از بازیابی، مسیر exe را بدهید؛ Enter برای شناسایی خودکار و 0 برای صرف‌نظر از dumper است.

Android

  1. بدون --apk/--lib در ترمینال، APKهای کنار خود اسکریپت نمایش داده می‌شوند، نه پوشهٔ جاری. می‌توانید مسیر دستی وارد کنید؛ مسیر نسبی APK دستی نسبت به پوشهٔ اسکریپت حل می‌شود.
  2. در نبود APK، مسیر دستی پرسیده می‌شود. این نسخه منوی انتخاب «APK یا فایل استخراج‌شده» ندارد؛ برای ورودی استخراج‌شده از CLI با --lib و --metadata استفاده کنید.
  3. اگر بیش از یک library یا metadata باشد، شماره را انتخاب کنید. برای تنها یک نامزد سؤال نمی‌شود. در حالت غیرتعاملی، چند نامزد خطاست.
  4. پس از دامپ موفق، اگر -f نداده باشید، پیشنهاد فیلتر با [Y/n] نمایش داده می‌شود (Enter یعنی بله).

هر دو نسخه arm64 را در مرتب‌سازی library مقدم می‌کنند. Windows در APK همیشه انتخاب شمارهٔ library و metadata را می‌پرسد، حتی با گزینه‌های CLI و حتی با یک نامزد؛ برای اتوماسیون بدون prompt از ورودی استخراج‌شده استفاده کنید.

Windows تا ۳۰ metadata محتمل با اندازهٔ ۴ کیلوبایت تا ۲۵۶ مگابایت و نام شامل metadata یا پسوند dat/bytes نشان می‌دهد. Android فقط نام پایهٔ global-metadata.dat یا sysinfo.dat را می‌پذیرد؛ ورودی‌های ZIP بزرگ‌تر از ۵۱۲ مگابایت کنار گذاشته می‌شوند.

فیلتر dump.cs و مدیریت اسمبلی‌ها

# Interactive menu / منوی تعاملی
python il2cpp_windows.py -fm -fi dump.cs
python il2cpp_android.py -fm -fi dump.cs
# Windows standalone automatic filter / فیلتر مستقل ویندوز
python il2cpp_windows.py -f -fi dump.cs -fo filtered.txt -a Assembly-CSharp.dll LogicAssembly.dll -k vip unlock
# Android standalone automatic filter: non-TTY stdin is required
# فیلتر مستقل خودکار اندروید: ورودی استاندارد نباید TTY باشد
python il2cpp_android.py -f -fi dump.cs -fo filtered.txt -a Assembly-CSharp.dll -k vip unlock < /dev/null
# Recovery + dumper + automatic filter / بازیابی، دامپ و فیلتر
python il2cpp_android.py --lib LIB --metadata META --out OUT --dumper-dir ~/Il2CppDumper-Python --no-clone -f -fo filtered.txt
python il2cpp_windows.py --lib LIB --metadata META --out OUT --dumper-exe "C:\Tools\Il2CppDumper.exe" -f -fo filtered.txt

-fm مستقیماً منوی فیلتر را باز می‌کند. گزینه‌ها: ۱ ورودی، ۲ خروجی، ۳ مدیریت DLL، ۴ نمایش keywordها، ۵ افزودن keyword، ۶ شروع فیلتر، ۰ بازگشت. مدیریت DLL از افزودن نام، حذف با شمارهٔ منفی، c پاک‌کردن، r بازنشانی و d انتخاب از headerهای dump پشتیبانی می‌کند. در Android برای افزودن نام فقط خود نام را بنویسید؛ علامت + را پیشوند نکنید.

اسمبلی‌های پیش‌فرض: ScriptsAssembly.dll، LogicAssembly.dll، Assembly-CSharp.dll، UtilsScripts.dll، Assembly-CSharp-firstpass.dll. گزینهٔ -a این فهرست را جایگزین می‌کند؛ -k به keywordهای پیش‌فرض اضافه می‌کند و تطبیق نام متد به‌صورت زیررشته است، نه regex.

فیلتر به headerهای // Image، TypeDefIndex، خطوط // RVA و متدهای دارای بدنهٔ { } متکی است. فقط نوع بازگشتی زیر مجاز است: bool, int, SafeInt, void, float, double, Single, Double, SafeFloat. signature دارای string، متدهای عمومی مانند ToString/GetHashCode و کلاس‌های مطابق الگوهای analytics، demo، test، debug و مشابه حذف می‌شوند. خروجی متن منتخب با namespace، کلاس، signature و RVA است؛ نه بازسازی بدنهٔ متد و نه DLL قابل‌اجرا برای dnSpy.

تفاوت‌های مهم: در Android، فیلتر مستقل -f فقط با stdin غیرتعاملی اجرا می‌شود؛ در ترمینال عادی ممکن است انتخاب APK را شروع کند. برای کار تعاملی از -fm استفاده کنید. منوی Android فقط -fi را از CLI می‌گیرد و مقادیر -fo/-a/-k را به تنظیمات منو منتقل نمی‌کند؛ آن‌ها را داخل منو تنظیم کنید. پس از دامپ، Android فایل ساخته‌شده را فیلتر می‌کند و -fi را در آن مسیر نادیده می‌گیرد. Windows این گزینه را مقدم می‌داند.

Windows نام اسمبلی را بدون حساسیت به حروف مقایسه می‌کند و پوشهٔ والد خروجی را می‌سازد؛ Android تطبیق اسمبلی حساس به حروف دارد و پوشهٔ خروجی فیلتر باید از قبل موجود باشد. همیشه ورودی و خروجی را متفاوت انتخاب کنید؛ Android محافظ جلوگیری از بازنویسی فایل ورودی ندارد. خروجی پیش‌فرض هر دو filtered_dnspy_dump.txt در پوشهٔ جاری است.

مرجع CLI و مسیر خروجی

Both / مشترک:
--apk APK | --lib LIB --metadata META
--out OUT                  # default: ./il2cpp_result
--no-dump
-f,  --filter
-fm, --filter-menu
-fi, --filter-input FILE
-fo, --filter-out FILE      # default: filtered_dnspy_dump.txt
-k,  --keywords WORD [WORD ...]
-a,  --assemblies DLL [DLL ...]
-h,  --help

Windows only / فقط ویندوز:
--dumper-exe EXE

Android only / فقط اندروید:
--dumper-dir REPOSITORY
--dumper-script FILE
--no-clone
--yes

ورودی را به یکی از دو شکل APK یا جفت library/metadata بدهید؛ آن‌ها را ترکیب نکنید. Windows ترکیب --apk و --lib را رد می‌کند؛ Android در صورت ترکیب، APK را مقدم می‌داند. در Android همواره همراه --lib، گزینهٔ --metadata را بدهید. -fi یا -fo به‌تنهایی فیلتر را فعال نمی‌کند؛ -f یا -fm لازم است.

مسیرهای CLI نسبی عموماً نسبت به پوشهٔ کاری فعلی‌اند؛ اسکن APK کنار اسکریپت و مسیرهای دستی wizard اندروید استثناهای توضیح‌داده‌شده‌اند. خروجی و فیلتر موجود ممکن است بازنویسی شوند؛ برای هر پروژه پوشهٔ تازه انتخاب کنید. کد 0 لزوماً به معنی ساخته‌شدن دامپ یا نگه‌داشتن متد در فیلتر نیست؛ پیام و فایل خروجی را بررسی کنید.

Android: نصب Ubuntu در proot و ساخت dumper رسمی (مسیر جایگزین دستی)

این بخش مسیر دستیِ باقی‌مانده از راهنمای قبلی است، نه قابلیت دو اسکریپت پیوست. نصب بسته‌ها و target framework مخزن باید با README و فایل csproj همان نسخه تطبیق داده شود؛ فرمان net8.0 تنها در صورت پشتیبانی پروژه معتبر است. این مسیر در این به‌روزرسانی روی دستگاه آزمایش نشده است.

این مسیر جایگزین به‌صورت مستقل و دستی اجرا می‌شود. توجه: اسکریپت موجود il2cpp_android.py فعلاً launcher دامپر Python یعنی Il2CppDumper-Python است؛ گزینهٔ --dumper-script فقط اسکریپت Python می‌گیرد و DLL را اجرا نمی‌کند. مراحل زیر ساخت و اجرای دستی نسخهٔ رسمی Perfare در Ubuntu هستند و مستقل از آن launcher انجام می‌شوند.

۱. Termux و Ubuntu

Termux را از F-Droid یا انتشار رسمی GitHub نصب کنید؛ روش نصب سازگار با دستگاه را از مستندات رسمی انتخاب کنید. در Termux (نه Ubuntu) اجرا کنید و دسترسی فایل را تأیید کنید:

pkg update && pkg upgrade -y
pkg install python proot-distro -y
termux-setup-storage
proot-distro install ubuntu:24.04
proot-distro login ubuntu:24.04

اگر alias نسخه‌ای شناخته نشد، proot-distro list را ببینید و یک alias موجود را در هر دو فرمان install/login به‌کار ببرید. Download معمولاً در Ubuntu با /sdcard/Download دیده می‌شود.

۲. نصب .NET و انتشار DLL داخل Ubuntu

این فرمان‌ها فقط در prompt مربوط به Ubuntu proot اجرا شوند. برای Ubuntu 24.04 روی arm64، SDK از مخزن Ubuntu نصب می‌شود؛ feed مایکروسافت اضافه نمی‌شود.

apt update
apt install -y python3 git dotnet-sdk-8.0
dotnet --version
git clone https://github.com/Perfare/Il2CppDumper.git /root/Il2CppDumper-src
dotnet publish /root/Il2CppDumper-src/Il2CppDumper/Il2CppDumper.csproj -c Release -f net8.0 --self-contained false -o /root/Il2CppDumper-bin
test -f /root/Il2CppDumper-bin/Il2CppDumper.dll && echo "Il2CppDumper DLL OK"

برای جلوگیری از مکث «press any key»، فقط RequireAnyKey را در تنظیمات منتشرشده false کنید و بقیهٔ تنظیمات را نگه دارید:

python3 - <<'PY'
import json
p='/root/Il2CppDumper-bin/config.json'
with open(p, encoding='utf-8') as f: c=json.load(f)
c['RequireAnyKey']=False
with open(p,'w',encoding='utf-8') as f: json.dump(c,f,indent=2)
print('RequireAnyKey =', c['RequireAnyKey'])
PY

۳. اجرای دستی DLL

پس از بازیابی معتبر metadata، اجرای رسمی به فرم dotnet DLL LIB METADATA OUTPUT_DIR است. این اجرای دستی جداست؛ برای APK باید lib و metadata را استخراج/انتخاب کنید. در فرمان زیر، خروجی مستقیماً در پوشهٔ خروجی داده‌شده ساخته می‌شود:

dotnet /root/Il2CppDumper-bin/Il2CppDumper.dll \
  /sdcard/Download/libil2cpp.so \
  /sdcard/Download/global-metadata.dat \
  /root/il2cpp_result

پوشهٔ خروجی باید قابل‌نوشتن و فضای ذخیره‌سازی کافی باشد. انتقال نمونه به Download:

mkdir -p /sdcard/Download/il2cpp_result
cp /root/il2cpp_result/dump.cs /sdcard/Download/il2cpp_result/

روش معمول داخل این بسته همچنان اجرای Python helper با Il2CppDumper-Python است؛ هیچ‌یک از دستورهای DLL را با --dumper یا --dumper-script اشتباه نگیرید.

۴. اجرای خودکار از Ubuntu proot

برای اجرای بدون prompt، ورودی‌های از قبل استخراج‌شده را در مسیرهای ثابت بگذارید و اجرای DLL را داخل Ubuntu انجام دهید. این نمونهٔ shell بررسی فایل‌ها و اجرای رسمی را پشت‌سرهم انجام می‌دهد؛ آن را با مسیرهای بازی خود تطبیق دهید:

LIB=/sdcard/Download/libil2cpp.so
META=/sdcard/Download/global-metadata.dat
OUT=/root/il2cpp_result
DLL=/root/Il2CppDumper-bin/Il2CppDumper.dll
test -f "$LIB" && test -f "$META" && test -f "$DLL" || { echo "Missing input/DLL"; exit 1; }
mkdir -p "$OUT"
dotnet "$DLL" "$LIB" "$META" "$OUT"
test -s "$OUT/dump.cs" && echo "Dump OK: $OUT/dump.cs"

این دستورها مسیر DLL و سه آرگومان ورودی/خروجی را می‌دهند؛ فایل APK را به DLL ندهید و اگر بازی metadata رمزگذاری‌شده/سفارشی دارد، ابتدا با روال مناسب metadata معتبر تهیه کنید. در اجرای دستی می‌توانید همان فرمان dotnet DLL LIB METADATA OUTPUT_DIR را در prompt وارد کنید. انتقال خروجی به حافظهٔ مشترک (در صورت نیاز):

mkdir -p /sdcard/Download/il2cpp_result
cp /root/il2cpp_result/dump.cs /sdcard/Download/il2cpp_result/

برای خروج از Ubuntu به Termux، exit را اجرا کنید. اجرای خودکار این بخش، launcher موجود il2cpp_android.py را فراخوانی نمی‌کند.

Windows · il2cpp_windows.py

Metadata recovery, running an existing dumper, and dump.cs filtering through an interactive menu and CLI. Requires Python 3.8+; the wrapper has no third-party Python dependencies. Windows is the host OS: the library input must be an Android ELF libil2cpp.so, not a native Windows GameAssembly.dll.

No dumper is downloaded. Obtain Il2CppDumper.exe separately and place it in the current directory or beside the script, or pass --dumper-exe.

python --version
python il2cpp_windows.py
# Extracted inputs / فایل‌های استخراج‌شده
python il2cpp_windows.py --lib "C:\game\libil2cpp.so" --metadata "C:\game\sysinfo.dat" --out "C:\il2cpp_result" --dumper-exe "C:\Tools\Il2CppDumper.exe"
# Recovery only / فقط بازیابی
python il2cpp_windows.py --lib LIB --metadata META --out OUT --no-dump
# APK: still prompts for candidate numbers / همچنان انتخاب شماره لازم است
python il2cpp_windows.py --apk "C:\game.apk" --out "C:\il2cpp_result" --no-dump

Recovery writes OUT/global-metadata.dat. APK mode also writes OUT/libil2cpp.so and OUT/metadata_input.bin. Extracted-input mode does not copy the library. The dumper receives the library path, recovered metadata path, and OUT/dump; its working directory is the exe directory.

The old positional LIB METADATA OUTPUT_DIR form is not supported. Use named options. A missing exe in CLI mode prints a message and returns code 2, retaining recovered metadata. In the recovery menu it only prints a message and returns to the menu. Windows checks the dumper exit code, but does not itself verify that dump.cs exists.

Android · Termux + Python Dumper

Dumper location and download consent

In a terminal, without --dumper-dir or --dumper-script, choose 1) home, 2) beside the script, or 3) a custom directory. This is a location choice, not an automatic search of multiple directories. A custom path has Il2CppDumper-Python appended unless it already has that directory name.

If missing, download requires confirmation with [y/N]; Enter declines. Non-interactive mode defaults to ~/Il2CppDumper-Python and permits download only with --yes. --no-clone disables downloading. A valid repository must contain il2cpp_dumper_py/__main__.py; an existing incomplete directory is an error.

# Use an existing repository / استفاده از مخزن نصب‌شده
python il2cpp_android.py --apk /sdcard/Download/game.apk --out ~/il2cpp_result --dumper-dir ~/Il2CppDumper-Python --no-clone
# Permit download if missing / اجازهٔ دانلود در صورت نبودن مخزن
python il2cpp_android.py --apk /sdcard/Download/game.apk --out ~/il2cpp_result --yes
# Extracted inputs; recovery only / فایل‌های استخراج‌شده؛ فقط بازیابی
python il2cpp_android.py --lib /sdcard/Download/libil2cpp.so --metadata /sdcard/Download/sysinfo.dat --out ~/il2cpp_result --no-dump

A repository is run as python -m il2cpp_dumper_py LIB META OUT/dump from its own directory. --dumper-script selects an existing file to run with Python and the same three arguments; do not supply a DLL or exe. The wrapper saves a copy of the input library and recovered metadata in OUT. Dump success requires exit code zero and a non-empty dump.cs in OUT/dump or OUT.

If the dumper is missing and downloading is declined or disabled, Android returns code 0 with recovered inputs only; this is not dump success. --no-dump also returns immediately after saving the inputs, so post-dump filtering does not run even with -f. This file contains no metadata_dump() function.

Interactive execution and APK selection

Windows

  1. No arguments opens the main menu: 1 recovery/run dumper, 2 dump filter, 0 exit.
  2. Recovery offers 1 APK or 2 extracted library + metadata; there is no default extracted-input mode.
  3. Enter paths and the output folder (default ./il2cpp_result). Use 0 to go back where indicated.
  4. After recovery, enter the exe path; Enter auto-detects it and 0 skips it.

Android

  1. Without --apk/--lib in a terminal, APKs beside the script, not in the current directory, are listed. A manual path option is available; relative manually entered APK paths are resolved against the script directory.
  2. If no APKs are found, a path is requested. There is no APK-versus-extracted-files wizard menu; use CLI --lib and --metadata for extracted inputs.
  3. Choose by number if multiple libraries or metadata candidates exist. A single candidate is selected without a prompt. Multiple candidates are an error in non-interactive mode.
  4. After successful dumping, without -f, a [Y/n] prompt offers filtering; Enter accepts.

Both versions sort arm64 libraries first. Windows APK mode always asks for library and metadata numbers, even with CLI flags or one candidate. Use extracted inputs for prompt-free automation.

Windows lists up to 30 plausible metadata files of 4 KiB–256 MiB with metadata in the name or a dat/bytes suffix. Android accepts only basenames global-metadata.dat or sysinfo.dat, ignoring ZIP entries larger than 512 MiB.

dump.cs filtering and assembly management

# Interactive menu / منوی تعاملی
python il2cpp_windows.py -fm -fi dump.cs
python il2cpp_android.py -fm -fi dump.cs
# Windows standalone automatic filter / فیلتر مستقل ویندوز
python il2cpp_windows.py -f -fi dump.cs -fo filtered.txt -a Assembly-CSharp.dll LogicAssembly.dll -k vip unlock
# Android standalone automatic filter: non-TTY stdin is required
# فیلتر مستقل خودکار اندروید: ورودی استاندارد نباید TTY باشد
python il2cpp_android.py -f -fi dump.cs -fo filtered.txt -a Assembly-CSharp.dll -k vip unlock < /dev/null
# Recovery + dumper + automatic filter / بازیابی، دامپ و فیلتر
python il2cpp_android.py --lib LIB --metadata META --out OUT --dumper-dir ~/Il2CppDumper-Python --no-clone -f -fo filtered.txt
python il2cpp_windows.py --lib LIB --metadata META --out OUT --dumper-exe "C:\Tools\Il2CppDumper.exe" -f -fo filtered.txt

-fm opens the filter menu directly: 1 input, 2 output, 3 DLL management, 4 show keywords, 5 add keyword, 6 filter, 0 back. DLL management supports adding names, removing negative numbers, c clear, r reset, and d selecting from dump headers. On Android enter DLL names directly; do not prefix them with a plus sign.

Default assemblies: ScriptsAssembly.dll, LogicAssembly.dll, Assembly-CSharp.dll, UtilsScripts.dll, Assembly-CSharp-firstpass.dll. -a replaces this list; -k adds to default keywords. Method-name matching uses substrings, not regular expressions.

The filter relies on // Image headers, TypeDefIndex, // RVA lines, and methods ending in { }. Allowed return types: bool, int, SafeInt, void, float, double, Single, Double, SafeFloat. Signatures containing string, utility methods such as ToString/GetHashCode, and classes matching analytics, demo, test, debug and similar patterns are excluded. Output is selected text with namespace, class, signatures and RVAs, not recovered method bodies or an executable DLL for dnSpy.

Important differences: Android standalone -f requires non-TTY stdin; in a normal terminal it may start APK selection instead. Use -fm for interactive work. Android's menu imports only -fi, not CLI -fo/-a/-k; configure these inside the menu. After dumping, Android filters the generated file and ignores -fi on that path. Windows gives -fi priority.

Windows compares assembly names case-insensitively and creates output parent directories. Android assembly matching is case-sensitive and filter output directories must already exist. Always use different input and output paths; Android has no same-file overwrite guard. Both default to filtered_dnspy_dump.txt in the current directory.

Android: Ubuntu under proot and build the official dumper (manual alternative)

This retained manual alternative is not a feature of either attached script. Check package availability and the repository csproj/README for the version used; net8.0 is valid only if supported by that project. This path was not device-tested in this update.

This is a separate manual alternative. Important: the included il2cpp_android.py currently launches the Python Il2CppDumper-Python; its --dumper-script option accepts a Python script, not a DLL. The steps below build and run the official Perfare version manually inside Ubuntu, separately from that launcher.

1. Termux and Ubuntu

Install Termux from F-Droid or the official GitHub releases; choose a compatible installation method from the official documentation. In Termux (outside Ubuntu), run and grant storage permission:

pkg update && pkg upgrade -y
pkg install python proot-distro -y
termux-setup-storage
proot-distro install ubuntu:24.04
proot-distro login ubuntu:24.04

If the versioned alias is unavailable, check proot-distro list and use one available alias consistently for install and login. Download is usually visible inside Ubuntu at /sdcard/Download.

2. Install .NET and publish the DLL inside Ubuntu

Run these commands only at the Ubuntu proot prompt. For Ubuntu 24.04 on arm64, install the SDK from Ubuntu's repository; this procedure does not add Microsoft's feed.

apt update
apt install -y python3 git dotnet-sdk-8.0
dotnet --version
git clone https://github.com/Perfare/Il2CppDumper.git /root/Il2CppDumper-src
dotnet publish /root/Il2CppDumper-src/Il2CppDumper/Il2CppDumper.csproj -c Release -f net8.0 --self-contained false -o /root/Il2CppDumper-bin
test -f /root/Il2CppDumper-bin/Il2CppDumper.dll && echo "Il2CppDumper DLL OK"

To avoid a “press any key” pause, set only RequireAnyKey to false in the published config and preserve other settings:

python3 - <<'PY'
import json
p='/root/Il2CppDumper-bin/config.json'
with open(p, encoding='utf-8') as f: c=json.load(f)
c['RequireAnyKey']=False
with open(p,'w',encoding='utf-8') as f: json.dump(c,f,indent=2)
print('RequireAnyKey =', c['RequireAnyKey'])
PY

3. Run the DLL manually

Once valid metadata is available, the official CLI form is dotnet DLL LIB METADATA OUTPUT_DIR. This is a separate manual run; for an APK, extract/select the library and metadata. For the command below, output is written directly to the supplied output directory:

dotnet /root/Il2CppDumper-bin/Il2CppDumper.dll \
  /sdcard/Download/libil2cpp.so \
  /sdcard/Download/global-metadata.dat \
  /root/il2cpp_result

Choose a writable output directory and ensure sufficient storage. Example copy to Download:

mkdir -p /sdcard/Download/il2cpp_result
cp /root/il2cpp_result/dump.cs /sdcard/Download/il2cpp_result/

The bundle's normal workflow still runs the Python helper with Il2CppDumper-Python; do not confuse these DLL commands with --dumper or --dumper-script.

4. Automated execution inside Ubuntu proot

For a non-interactive run, place already-extracted inputs at stable paths and invoke the DLL inside Ubuntu. This shell example checks the files and runs the official dumper in sequence; adjust paths for your game:

LIB=/sdcard/Download/libil2cpp.so
META=/sdcard/Download/global-metadata.dat
OUT=/root/il2cpp_result
DLL=/root/Il2CppDumper-bin/Il2CppDumper.dll
test -f "$LIB" && test -f "$META" && test -f "$DLL" || { echo "Missing input/DLL"; exit 1; }
mkdir -p "$OUT"
dotnet "$DLL" "$LIB" "$META" "$OUT"
test -s "$OUT/dump.cs" && echo "Dump OK: $OUT/dump.cs"

These commands supply the DLL path and its three input/output arguments. Do not pass an APK as the DLL input; if a game uses custom/encrypted metadata, first obtain valid metadata using an appropriate workflow. For a manual run, enter the same dotnet DLL LIB METADATA OUTPUT_DIR command at the prompt. To copy the result to shared storage if desired:

mkdir -p /sdcard/Download/il2cpp_result
cp /root/il2cpp_result/dump.cs /sdcard/Download/il2cpp_result/

Run exit to leave Ubuntu and return to Termux. This automated section does not invoke the bundled il2cpp_android.py launcher.
